# 系统如何工作

## 三个运行位置

| 位置 | 运行内容 | 不应持有的权限 |
| --- | --- | --- |
| CloudBase | 静态网站、身份认证、PostgreSQL 业务函数、私有文件 | 浏览器不持有数据库管理员 Key |
| Codex Cloud | 指定作业的下载、识别、翻译、质量检查和回传 | 不能改成员角色、批准自己稿件、发人工积分 |
| 腾讯云服务器或其他 Linux 主机 | AstrBot、QQ 身份映射、定时通知、受限清理 | 不使用组长网页登录令牌冒充组长 |

网站是原生 HTML/CSS/JavaScript，不依赖一个常驻 Node 网站服务器。后端主要是 PostgreSQL 函数，由 CloudBase 的 REST/RPC 网关调用。`SECURITY DEFINER` 函数是受控业务入口，函数内必须检查调用身份、项目归属和状态；并不是给前端直接开放整张表。

CloudBase 的 PG 模式使用 GRANT 与 RLS 两层控制；身份令牌把当前用户带到数据库。`service_role` 能绕过 RLS，不能放进网页或普通工作器。本仓库同时保留旧部署与文档所示身份表差异的兼容读取，但仍需在你自己的环境验收。[官方 PG 身份与权限说明](https://docs.cloudbase.net/authentication-v2/auth/auth-pg)

## 主要数据

| 表或表组 | 用途 |
| --- | --- |
| `st_members`、`st_roles`、`st_member_roles` | 成员、全局角色与状态 |
| `st_project_members`、`st_projects` | 项目与项目内身份 |
| `st_tasks`、`st_claims` | 任务和认领历史；每项任务最多一个有效认领 |
| `st_uploads`、`st_artifacts`、`storage.objects` | 上传、文件归属、分片与校验 |
| `st_deliveries`、`st_reviews` | 不覆盖的交付版本和审核记录 |
| `st_contributions`、`st_point_entries`、修正记录 | 可核验贡献、积分和更正历史 |
| `st_cloud_workers`、`st_cloud_jobs` | 执行身份、作业授权、租约和请求额度 |
| `st_subtitle_requests`、通知事件表 | 组员申请、审批、通知来源 |
| `st_qq_gateways`、`st_qq_links`、`st_qq_codes` | 受限机器人身份、成员映射、一次性码 |
| `st_source_retention`、`st_purge_jobs`、`st_purge_objects` | 原视频保留期、精确文件清理任务 |
| `st_audit_events` | 关键业务操作的审计记录 |

迁移清单见 `database/migrations.json`。编号不是连续序号：有些旧编号是测试或仅修复特定历史数据，未作为新环境安装的一部分。三个 `recorded_*` 文件恢复了之前在线修正的函数定义，**仅含定义，不含生产数据**。它们让首次安装不再依赖私人数据库快照。

## 权限矩阵

“允许”仍需要满足项目归属、任务负责人、状态等条件。

| 能力 | 普通成员 | 项目审核员 | 项目负责人 | 组长 | Cloud 工作器 |
| --- | --- | --- | --- | --- | --- |
| 查看开放工作、认领 | 是 | 是 | 是 | 是 | 否 |
| 查看项目内部资料 | 已有项目权限 | 本项目 | 本项目 | 按业务管理范围 | 仅授权作业 |
| 提交本人交付 | 是 | 是 | 是 | 是 | 仅 AI 交付接口 |
| 审核交付 | 否 | 本项目且不是本人稿件 | 本项目且不是本人稿件 | 仍受自审限制 | 否 |
| 修改项目/任务 | 按本人/项目规则 | 按项目规则 | 本项目 | 是 | 否 |
| 修改成员身份、积分修正 | 否 | 否 | 否 | 受控且审计 | 否 |
| 创建/撤销 Cloud 身份 | 否 | 否 | 否 | 是 | 否 |
| 永久删除 | 否 | 否 | 否 | 仅指定的一名组长 | 否 |

QQ 网关只可通过固定接口查询必要信息、读取通知和处理明确授权的精确清理任务；它没有通用 SQL 执行接口。普通聊天模型不会收到绑定码和业务密钥，固定命令先于模型处理。

## 文件和费用的一致性

视频按分片上传，登记 SHA-256、大小和归属。领取作业后工作器重新核验文件，并验证真实时长。下载来源只接受配置的 HTTPS 网关；认证请求不跟随重定向。

每次付费请求前先取得服务端额度预留和有效租约，再记录本地账本。断线后不确定某次请求是否已经扣费时，任务停在待核对状态，不自动重复发送。换机器或删除本地目录不能恢复服务端额度。

正常交付包含九个私有字幕/报告文件，精确名单由 `worker/delivery_contract.py` 定义。回传失败与模型结果不确定不同：仅在检查点和作业状态允许时，才使用只回传模式。工作器不会因为上传失败重新翻译一遍。

人工审核、贡献和积分由数据库事务管理。积分更正保留修正记录，不悄悄重写历史。AI 交付仍需要人工检查，不自动算作人工劳动。

## QQ 为什么不是一直查数据库

`schedule.py` 每 15 秒只看服务器本地时钟；到了每天四个时段才通过固定接口查询云数据库。每个时段在本地 SQLite 中登记一次，防止重启或重复进程造成同一时段反复轮询。消息结果不确定时暂停相应通道，保留回执供人工核查。

定时检查减少调用量，但不会保证 PostgreSQL 本身零计算费用。数据库费用、模型请求费和机器人服务器费用要分别看。
