原 GitHub 私有仓库只保存了较早的工作器版本；较新的网站、数据库与机器人代码散落在多个部署目录。本仓库以最后保存的有效源码和发布资料整理，并把早期仓库源码放进 experiments/initial-worker/。旧仓库的历史没有原样公开，以免把私人部署资料或未审查的历史一并暴露。

公开版本号是社区源码版本，不等于某个账户的 Cloud 环境版本。别人的环境不会自动继承原项目的额度、网络和凭据。

公开到什么程度

业务实现、可复用脚本、测试、配置样例和技术方法全部纳入。以下内容并非可安全发布的项目源码，因此用模板、说明或上游链接替代：

  • 密钥、密码、验证票据、SSH 私钥、账号配置、真实 QQ 身份与成员资料。
  • 生产数据库导出、通知回执账本、备份、已签名文件地址和实际字幕/视频。
  • 私人聊天原文、含账号信息的控制台截图、现场调试日志。
  • 云平台本身、Codex/ChatGPT 本身、第三方模型服务或不属于本项目的代码。
  • 下载的依赖、模型权重和 AstrBot 管理界面二进制：提供安装方式和许可来源。
  • 缺乏独立来源记录的原网站插画：公开版使用仓库内新绘制的简单 SVG，保留页面布局与功能。

“开源”不意味着把组员的隐私或其他作者的稿件一同公开；也不意味着能把腾讯云、OpenAI 和 QQ 的服务端软件变成这个仓库的一部分。

为什么保留半自动

字幕量不大时，组长在 QQ 看提醒、回网站审批、再复制指令到 Cloud，已经能减少大量重复操作。这个人工步骤同时让人核对素材、费用和授权。

experiments/dispatcher/ 留下了一键启动的实现尝试，但本项目没有验证出可供网站稳定使用的正式 Cloud 自动启动连接，因此默认关闭。它不是部署步骤，也不能拿个人登录 Cookie 自动模拟后台登录。

云端剪辑代码保留在工作器的 clip_* 文件和 website/ 历史实验中；该方案未形成可靠的正式流程，当前网站不加载相应板块。人工剪辑任务与视频交付仍是正常功能。

社区可以继续改什么

优先欢迎：更简洁的安装与升级、实际 CloudBase 验收、成本监测、可恢复的文件备份、字幕质量评估，以及兼容不同授权供应商的明确适配层。

尚未完成的目标不要在界面上标成可用。新的翻译渠道、完整自动调度或陌生 Agent 接入，需要独立的权限、计费和重复执行测试。
