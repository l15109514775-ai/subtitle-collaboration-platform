# 开发与测试

## 环境与入口

网站无需构建工具，`site/index.html` 引用完整脚本和样式。部署时使用 `tools/configure.py` 生成副本，源文件保持通用占位符。

Python 工作器生产运行在 Linux，使用 `worker/requirements.lock` 的固定依赖和 `worker/model.lock.json` 的固定模型版本。Windows 适配测试只验证逻辑，不证明 POSIX 文件锁、fsync 或 Linux 生产持久性。模型下载器核对文件尺寸和摘要，不使用不明镜像替代失败下载。

Node 测试使用 PGlite，在内存中运行真正的 PostgreSQL SQL 逻辑，平台身份认证和存储元数据由虚构适配器提供。它不能代替 CloudBase 的实际网关、JWT 签名、文件字节、并发连接或备份恢复测试。

## 本地检查

需要 Node.js 22 或更新版本及 Python 3.11 或更新版本。安装 Node 测试依赖：

```text
npm ci
npm test
python tools/check_release.py
```

机器人测试不需要接通 QQ，也不会发消息：

```text
python -m unittest discover -s tests/bridge -p "test_*.py"
python -m unittest discover -s tests/notifications -p "test_*.py"
```

工作器的离线测试需要 NumPy、FFmpeg 与中文字体；不必下载模型权重。先在仓库根目录安装小型测试依赖，再进入工作器目录：

```text
python -m pip install -r requirements-test.txt
cd worker
python run_offline_tests.py
```

在 Windows 上改用 `python run_offline_tests.py --windows-adapter`。其输出会明确记录跳过项和持久性验证限制。没有中文字体时，字体相关测试可能跳过；Linux 完整验收应安装中文字体后再跑。

测试模拟网络和费用请求，使用虚构凭据，不应拿真实模型 Key 运行测试。不要将 `.env`、截图、模型文件或实际稿件提交进仓库。

## 数据库修改

`database/migrations.json` 是安装顺序的唯一清单。新迁移写成独立文件，先使用隔离数据库测试。不要改正在运行的生产数据去验证越权、删除和并发行为。

至少覆盖：匿名与普通成员权限、跨项目读写、本人交付限制、自审限制、身份撤销、重复审核、文件归属、精确清理、请求结果不确定和重复通知。

数据库函数使用固定 `search_path`，对执行权限显式授权/撤销，不能依赖前端隐藏按钮。更改 `SECURITY DEFINER` 函数、RLS、网关 scope 或永久删除能力都应单独审查。

## 本次整理中的代码调整

- 合并了当前网站所需的全部静态文件和已部署的功能叠加脚本。
- 把原账号环境地址换为占位符，通过工具生成自己的部署副本。
- 重建从空库可执行的迁移链，去掉按默认用户名自动赋予组长的行为，改为明确用户 ID 的一次性初始化。
- 对身份认证表中的 `sub`/`id` 表示差异使用显式兼容读取，新增隔离验证。
- 把原电脑绝对路径和私人数据库快照依赖从可运行测试中移除。
- 保留旧实验及历史测试参考，但不把其成功记录当作当前版本的验收。
- 文字渠道默认使用不可连接的示例域名；配置后固定目标地址，继续拒绝把 bearer 凭据跟随重定向发送。

本次没有改动原站生产权限、Cloud 凭据、QQ 绑定或云资源套餐。公开代码不是对原环境进行迁移。

## 内测注册回归

`npm test` 同时运行注册流程回归：用户名格式失败时不得调用邮箱验证码核验或注册接口；6/25 位边界、大小写、起始字符、点号和已有邮箱登录均使用模拟网络测试，不创建真实账号。

## 发布检查

运行 `tools/check_release.py`，确认没有真实环境 ID、机器路径、密钥、私有媒体、运行账本、节点依赖目录或生成部署包进入发布集合。它是规则扫描，不是安全保证；人工检查新增配置及 Git 历史仍然必要。

CI 只执行离线测试和源码扫描，不上传或部署到腾讯云，不接通 QQ，不调用收费模型。正式发布仍要核对实际平台配置和第三方许可证。

需要了解文件由来时看 `SOURCE_MANIFEST.json`。技术设计与用户教程分别放在 `docs/`，不要把只在某台电脑上可执行的路径写进主教程。
