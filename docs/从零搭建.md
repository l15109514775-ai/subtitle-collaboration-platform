# 从零搭建：给没有编程经验的字幕组管理员

你不需要先学编程，但第一次搭建需要耐心完成几个平台的设置。建议用电脑完成首次配置，之后可以用安卓手机处理申请和启动云任务。先搭一个只有你自己使用的测试环境，成功后再邀请组员。

遇到本文没有出现的收费确认、账号验证或权限提示，先停在该页面，核对它是否属于你打算开通的服务。任何人协助你时，都不需要你把密码、验证码或密钥发进聊天。

## 0. 先认识五样东西

| 名字 | 可以把它理解为 | 你要做的事 |
| --- | --- | --- |
| 网站 | 字幕组的办事窗口 | 上传页面文件，取得一个网址 |
| CloudBase PostgreSQL | 保管成员、任务和权限的档案柜 | 新建环境，安装数据库结构 |
| Codex Cloud | 远程运行字幕程序的工作电脑 | 配置环境，人工启动每个作业 |
| 模型服务 | 负责识别和翻译的外部服务 | 配置你获准使用的模型凭据和额度 |
| AstrBot + QQ 插件 | 传消息、查状态的值班机器人 | 放在常开的服务器上，绑定 QQ |

腾讯云服务器只运行机器人及通知调度，不承担视频识别与翻译。电脑关闭后服务器仍可发通知；已经启动的 Cloud 任务由云环境运行。

## 1. 准备账号和下载文件

需要自己的腾讯云账号、可使用 Codex Cloud 的 ChatGPT 账号、GitHub 账号，以及管理 QQ 机器人的 QQ 账号。不同平台的登录彼此独立；登录腾讯云控制台不会自动登录字幕网站。

先不要购买大规格服务器，也不要把别人的 Key 填进来。可以先完成网站阶段，再决定是否接 Cloud 和 QQ。

在仓库首页点击绿色 **Code**，再点 **Download ZIP**。下载后右键 ZIP，选择“全部解压”。不要直接在压缩包里运行文件。把解压目录放在自己方便备份的位置，例如 `D:\字幕协作台`。

Windows 需要 Python 3.11 或更新版本来生成配置文件。没有安装时，从 [Python 官网](https://www.python.org/downloads/) 下载；安装界面勾选 **Add Python to PATH**。本工具只使用 Python 自带模块，不要求先安装其他 Python 库。

## 2. 创建一个自己的 CloudBase 测试环境

1. 打开 [腾讯云 CloudBase 控制台](https://tcb.cloud.tencent.com/)，自行登录。
2. 新建环境，选择你需要的地域和 **PostgreSQL / PG 模式**。如果创建成传统文档数据库模式，本项目的 SQL 无法直接使用。
3. 给环境起名，例如 `subtitle-community-test`。复制页面显示的**完整环境 ID**，不是自己填写的简短名称。
4. 查看套餐计费说明、资源点和数据库计算费用，只有你接受费用后才开通。
5. 在“静态网站托管”找到默认 HTTPS 网址。记录它，仅用于开发测试。准备正式域名时，按 [域名与证书](域名与证书.md) 完成备案、DNS 验证和 HTTPS 验收。

**成功标志：** 控制台里能打开 PostgreSQL 数据库和 SQL 编辑器，环境状态正常，套餐资源没有耗尽。

不要以为访问量少就一定免费：数据库计算也可能持续消耗额度。具体请阅读 [维护与排错](维护与排错.md)。

## 3. 创建自己的组长登录账号

在该环境的“身份认证 / 用户管理”中创建或注册自己的账号，启用你需要的用户名密码和邮箱验证登录方式。邮箱注册、找回密码都依赖云平台的邮件与验证配置。

建议给组长账号绑定自己能长期访问的邮箱，使用不同于腾讯云控制台的独立密码。复制该用户的 **用户 ID / 登录主体 ID**。它不是邮箱、QQ 号、用户名，也不是 `st_members` 表里的成员 UUID。

**成功标志：** 在控制台的用户列表能看到刚创建的账户，并能找到它的用户 ID。此时它还不是网站业务组长，下一步会明确指定。

## 4. 生成你的部署包

在解压目录里双击 `开始配置.cmd`。黑色窗口是本地配置工具，不是远程登录页面。按提示输入：

| 提示 | 从哪里取得 |
| --- | --- |
| 完整环境 ID | 第 2 步的 CloudBase 环境详情 |
| 静态网站 HTTPS 地址 | 第 2 步的网站托管默认网址 |
| Cloud 环境名 | 可以先按回车，使用 `subtitle-delivery-20min-active` |
| 文字服务地址 | 自己获得授权的、支持 `/v1/responses` 的服务；暂时不接 Cloud 可留空 |
| 文字模型名 | 服务方提供的模型标识；必须与该渠道实际支持的模型一致 |
| 组长用户 ID | 第 3 步的身份认证用户 ID |

这里**不填写**任何密码或模型 Key。工具生成的 `build/deployment/` 只在你电脑上，不会自动上线。已经存在同名输出目录时工具会停止；要重新生成，可以把旧目录改名保留，再运行。

工具也支持开发者使用：`python tools/configure.py --config config.local.json --out build/my-deployment`。`config.local.json` 可以按根目录示例填写，不能提交到公共仓库。

**成功标志：** 看到“已生成”，打开 `build/deployment` 可以找到 `site`、`database`、`worker`、`bot` 等目录。

## 5. 安装数据库，指定第一位组长

只对第 2 步创建的**全新空环境**执行。不要对已有业务数据的环境重复安装。程序会拒绝检测到现有业务表的安装。

1. 用记事本打开 `build/deployment/database/INSTALL_ALL.sql`，全选并复制。
2. 回 CloudBase → PostgreSQL → SQL 编辑器，粘贴并执行。
3. 确认全部成功后，再打开同目录 `SET_FIRST_OWNER.sql`，复制到 SQL 编辑器执行。
4. 如第一份 SQL 报错，不要继续执行后续步骤，也不要“放开所有权限”消除错误；保存错误代码和失败语句位置，按排错文档处理。

安装 SQL 使用一个事务：只要中途失败，整个安装不应被提交。若控制台对脚本长度有限制，需要管理员按 `database/migrations.json` 的清单顺序执行各文件；在全部完成、组长指定并验收前，不邀请任何成员进入环境。

第一位组长根据你明确填写的认证用户 ID 指定。系统不会把“第一个注册的人”或名字叫 `administrator` 的人自动提升为组长。

**成功标志：** 两份 SQL 均完成，数据库里出现以 `st_` 开头的业务表。表权限默认受限；普通成员直接读不到密钥表是正常表现。

## 6. 上传网站并验证账号

在 CloudBase → 静态网站托管里上传 `build/deployment/site/` **里面的文件**。确保托管根目录直接有 `index.html`，而不是多套了一层 `site` 文件夹。也可以使用生成的 `website-upload.zip`，前提是控制台提供“解压部署”功能；仅上传 ZIP 本身不会展开网站。

按 CloudBase 当前界面为自己的网址配置登录安全域名及必要的跨域允许来源。只添加自己的确切 HTTPS 来源；不要为了方便填任意来源或关闭鉴权。

打开默认网址，用第 3 步的账号登录。能看到成员管理、云执行身份等组长入口，说明认证和业务身份已连接。

用另一个邮箱注册一个虚构测试成员：它应先等待组长批准，不能立刻看见内部项目。组长审批后创建一个“安装验收”项目，检查认领、上传一份自制 ASS 字幕、提交、由另一个有审核权限的人审核。不要使用真实未公开稿件验收。

**成功标志：** 组长、待批准成员、正式成员看到的入口不同，未登录时访问不到内部数据。单靠登录成功不等于权限验收完成。

## 7. 配置 Codex Cloud 字幕环境

这一阶段需要模型渠道的合法使用权限和网络可达性。源码并不赠送模型额度，也不会继承原项目的账户和环境。

1. 在自己的 GitHub 账号下创建一个**独立的私有部署仓库**。如果目的是参与公开开发，也可以 Fork 本仓库；公开 Fork 不能直接改成私有仓库。
2. 将第 4 步生成的 `worker/` 上传到部署仓库，保留 `worker/` 这一层目录。生成内容不包含模型凭据。不要上传整个 `build`、账号文件或服务器 `data`。
3. 在 ChatGPT 网页或桌面端进入“设置 → Codex Cloud → 环境”，创建环境，选择自己的部署仓库。
4. 把环境命名为第 4 步填写的名称，让配置过程安装 Python、FFmpeg、中文字体，再在仓库 `worker/` 中运行 `bash setup_runtime.sh`。它会下载依赖及固定版本的 Whisper 模型，需要网络和磁盘空间；不会调用翻译/识别收费 API。
5. 在仓库的 `worker/` 目录运行 `.venv/bin/python run_offline_tests.py` 与 `.venv/bin/python runtime.py check --load-model`。缺少模型或依赖时先修复，不要把失败当作已完成。
6. 网络只允许实际需要的包仓库、模型下载域名、自己的 CloudBase 网关、文字服务和千问服务。保留环境代理与证书校验。

接着，在网站以组长身份进入“云端字幕交付 → 云执行身份设置”，创建一个身份，复制只显示一次的密钥。它用于网站对字幕程序授权。

| 变量 | 放在哪里 | 值来自哪里 |
| --- | --- | --- |
| `SUBTITLE_PLATFORM_TOKEN` | 环境变量 | 网站创建的云执行身份密钥 |
| `SUBTITLE_PLATFORM_GATEWAY_KEY` | 环境变量 | **自己的** CloudBase Publishable Key，角色必须是 `anon` |
| `SUBTITLE_GPT_TOKEN` | 网络机密；仅允许自己文字渠道域名 | 自己的文字服务凭据 |
| `SUBTITLE_QWEN_TOKEN` | 网络机密；允许 `dashscope.aliyuncs.com` | 自己的千问识别凭据 |

不使用 `service_role` 管理 Key。程序需要直接读取前两项做校验；模型凭据通过 Cloud 环境允许的网络机密机制交付。不要把任何密钥写进仓库、任务指令或 QQ。

保存配置，完成检查后“发布 / 重新发布”环境。从启动器**新建一个任务**再验证，已有任务可能仍使用旧状态。环境备注名和网站身份名可以不同，真正连接两者的是 `SUBTITLE_PLATFORM_TOKEN`。

先上传你自己制作的 10–30 秒视频，在网站审批较低的请求上限；检查费用后，复制该作业的云端指令，粘贴到新 Cloud 任务。工作目录应是仓库的 `worker/`。先看根目录 [PRODUCTION_FLOW.md](../PRODUCTION_FLOW.md) 的执行说明。

**成功标志：** 任务由“待人工启动”进入处理状态，最终网站出现 ASS/SRT 和报告，随后仍等待人工审核。没有接通的模型渠道、超限视频或身份不匹配都应停止并报明原因。

当前 Cloud 环境入口以 [OpenAI 官方说明](https://learn.chatgpt.com/docs/environments/cloud-environments) 为准。原项目选择的文字渠道受到特定授权规则限制；本版本仍不自动改用官方 OpenAI 文字 API。更换供应商应由部署者核对授权、数据处理范围、响应协议和费用，再做小样测试。

## 8. 把 QQ 机器人放到自己的服务器

先准备自己的 Linux 服务器，建议 Ubuntu，并参照 [Docker 官方 Ubuntu 安装说明](https://docs.docker.com/engine/install/ubuntu/) 安装 Docker Engine 与 Compose。购买服务器由你自己确认费用。

把 `build/deployment/` 上传到服务器一个独立目录，例如 `/opt/subtitle-platform-deployment`。再把里面 `ops/compose.yaml`、`ops/deploy.sh` 放到 `/opt/subtitlebot`，在该目录运行 `bash deploy.sh`。如果不知道如何上传或打开服务器终端，可按 [请助手协助搭建](请助手协助搭建.md) 让助手操作；涉及购买、登录和密钥填写的步骤仍由你确认。

机器人管理面板只监听服务器本机。电脑在终端运行下面的命令，替换尖括号内的内容，不保留尖括号：

```text
ssh -N -L 6185:127.0.0.1:6185 <服务器用户名>@<服务器地址>
```

保持该窗口开着，在电脑浏览器打开 `http://127.0.0.1:6185`。这是通过 SSH 访问自己服务器的本机管理面板。首次密码、后续改密由你自己设置；不要把 6185 端口开放给整个互联网。

在 AstrBot 中创建“QQ 官方机器人（WebSocket）”，按页面提供的方式扫码或配置自己的机器人。手机 QQ 中将它加入自己的测试群，并启用“机器人主动在群聊内发言”。QQ 的主动消息资格、频率和账号要求以平台当前规则为准。

接下来在服务器执行：

```text
python3 /opt/subtitle-platform-deployment/tools/configure_bot.py --deployment /opt/subtitle-platform-deployment --data /opt/subtitlebot/data
```

它会询问 AppID、AstrBot 平台实例 ID、组长认证用户 ID，以及隐藏输入的 Publishable Key。它在服务器生成新的受限网关密钥并保存在权限受限文件中，**不会打印密钥**。

把它生成的 `REGISTER_GATEWAY.sql` 内容放到自己的 CloudBase SQL 编辑器执行。此文件只含密钥的校验摘要及你的配置标识。然后重启 AstrBot，让两个插件加载。详细 QQ 平台步骤参考 [AstrBot 官方接入说明](https://docs.astrbot.app/platform/qqofficial/websockets.html)。

**成功标志：** AstrBot 能显示两个字幕插件，QQ 私聊能响应“字幕帮助”，没有让模型自行解释绑定码。

## 9. 绑定组长、测试两路提醒和审批指令

1. 组长私聊机器人发送 `字幕绑定`。将它返回的一次性码填入网站“QQ 账号绑定”，以当前组长登录状态确认。
2. 再私聊 `字幕通知设置 群聊`。
3. 把返回的整行 `字幕通知绑定 ……` 发到测试群，并 @ 机器人；收到群绑定成功回执。
4. 私聊 `字幕通知设置 双通道`，收到“群聊+私聊”确认。
5. 私聊 `字幕通知状态`，确认启用、目标和待核对数量。
6. 在网站提交一份虚构申请，等待下一个检查时段。群里应正确 @ 你，私聊应有同一申请提醒。
7. 在网站审批该申请；下一个检查时段应私聊云端执行指令。核对作业号，然后自行决定是否执行。

不要只看“发送成功”就认定正确 @；需要自己在 QQ 中检查可点击的账号提及。也不要删掉通知账本尝试重发，这可能导致重复消息。

## 10. 最后再开放给组员

先完成 [验证状态](验证状态.md) 中的线上验收清单。确认备份、费用提醒、两个普通账号的权限边界、私有下载和异常恢复，再邀请少量组员。

原视频 7 天清理与硬删除代码已包含，但新部署默认不启用自动清理。你明确接受保留期后，按 [维护与排错](维护与排错.md) 启用；硬删除仅授予指定的一名组长。

建议第一次完整验收后保存自己的环境 ID、网址、仓库版本和操作记录到私人文档中。记录“密钥保存在哪里”，不要记录密钥明文。以后升级先在测试环境验证，保留可以回退的版本。
