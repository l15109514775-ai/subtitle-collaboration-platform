维护、费用和故障排查

日常维护

每天查看申请积压、失败/待核对任务、QQ 待核对回执和资源用量。每次准备升级前，记录当前源码版本、数据库迁移版本，备份数据库与文件，并在隔离环境验证。

新代码发布不要覆盖运行数据。网站更新先传新版本脚本与样式，最后传引用它们的 index.html。数据库升级逐项审查；INSTALL_ALL.sql 只用于首次空环境安装，不能当升级脚本重复跑。

费用分开看

账单主要来源控制方法
CloudBase数据库计算、存储、网关、网络等资源预警、套餐用量、上传保留期
机器人服务器常驻云主机和流量只跑机器人，不在这里处理视频
Codex Cloud你的账户或组织的使用额度人工审批、按需启动、任务结束后停止
识别与翻译服务按请求、音频时长或 Token 计费每作业上限、账本和小样测试

不要把“每天只查四次数据库”理解为“数据库只收费四次”。原项目在访问量很低时也遇到过体验额度耗尽、PG 暂停，导致登录同时失败。套餐到期、配额用尽与网络故障是不同问题，先看控制台状态再处理。

本仓库不提供固定费用承诺，也没有替你开通按量付费。依赖下载和模型文件下载不等于调用收费识别模型，但云服务可能收取存储或流量费。

身份泄露时先撤销对应身份，检查正在执行的任务和审计，再生成新凭据。公开 Issue 不收密钥。如果密钥已经提交过 Git，仅删最新文件不够，必须先撤销，再清理历史。

启用 7 天原视频清理和硬删除

安装代码不会自动删除你的文件。确认“原视频上传完成后至少保留 7 天、字幕和报告继续保留”符合本组规则后，管理员执行以下步骤：

  • 1. 在 CloudBase SQL 编辑器查出本次部署的组长成员 ID 与 QQ 网关 ID；不要使用身份认证用户 ID 代替成员 ID。
  • 2. 执行下面的配置，把两个值换成真实 UUID。只指定一位组长，首次配置才使用此语句。
INSERT INTO public.st_purge_config(id,owner_id,gateway_id,enabled)
VALUES(1,'组长成员UUID','本组QQ网关UUID',true);
  • 3. 在服务器运行本仓库 tools/enable_cleanup.py --data /opt/subtitlebot/data --confirm-seven-day-policy。它只修改已有通知配置的清理开关，保留绑定与账本。下一次检查才会处理满足条件的任务。
  • 4. 用虚构文件验收：未满 7 天不能清理；运行中或待核对任务不能清理；原视频清理不能误删字幕；非指定组长不能永久删除。

到期时间不是精确到秒的删除承诺。网络故障、服务器停机或保护条件都会延迟清理；应查看清理记录，不能只凭到期日期认定文件已消失。

关闭自动清理时，将服务器同一设置设为 false；不要删除保留期表、任务表或通知账本。关闭并不恢复已经永久删除的文件。

备份与恢复：代码仓库不是备份

你需要分别保护：

  • 1. PostgreSQL 的业务表、权限和函数；账号系统按云平台支持的方式备份。
  • 2. 私有存储桶中的真实文件。备份 storage.objects 只有元数据，并没有保存视频与字幕的文件字节。
  • 3. AstrBot 的整个 data/，包括配置、绑定、回执 SQLite 及其 WAL 等相关文件。
  • 4. Cloud 的请求账本与未回传结果。任务等待核对时尤其不能丢弃。

生产数据库优先使用云平台当前支持的备份功能，并在独立环境恢复验证。机器人数据备份应先停止容器、完整复制 data/，再启动；不要只备份某一个正在写入的 SQLite 文件。备份目录只允许管理员访问，跨机器保存前加密，并测试解密方法。

仓库中保留了旧 Windows DPAPI 加密工具，见 ops/legacy-secure-backup.mjs；它是加密已有导出文件的辅助工具，不是自动数据库备份系统。DPAPI 通常绑定原 Windows 用户/机器，不能把这种备份当作唯一的异地恢复方案。

恢复演练必须在隔离环境完成：比对成员、任务状态、交付文件 SHA-256、积分流水和消息回执。先关闭 QQ 通知和清理，避免恢复历史数据后误发消息或误删文件。验证成功后再决定是否启用。

常见故障

现象先检查不应该做
网站打不开是否上传到了根目录、域名和托管状态反复改数据库权限
登录报 res_stopped / ResourceExhaustedCloudBase 套餐、资源点、PG 状态以为是密码错而连续重置
新用户无法看项目是否批准入组、是否属于项目给所有登录用户整表权限
Cloud 环境启动器不显示是否已发布、账号与工作区是否正确不断创建同名环境

源视频授权过期网站允许时刷新同一作业的授权改文件地址绕过来源验证
QQ 没提醒下个时段、插件启用、群绑定、主动消息权限每秒轮询或不断创建测试申请
群里没真正 @是否使用真实群内身份与 Markdown 消息格式拼 QQ 号代替群 openid

回传失败作业状态、原结果完整性、可否只回传默认重新识别和翻译

反馈时提供版本、操作步骤、期望结果和已脱敏的错误编号。网站的“复制反馈摘要”有意不包含完整请求体、令牌和稿件，优先使用它。

更新机器人插件

停止容器并备份 data/。把生成的两个插件源目录替换到 data/plugins/ 对应位置，再启动并查看插件版本。不要运行首次配置工具覆盖 subtitle_bridge.json、subtitle_notifications.json 或任何 SQLite 账本。 插件版本升级与数据库迁移需要一起检查兼容性。

ops/dashboard-* 和对应 systemd 文件是原部署网络诊断工具，只有普通 SSH 面板访问出现同类问题时才研究。默认部署不需要它们，也没有打包 AstrBot 的第三方管理界面二进制。
